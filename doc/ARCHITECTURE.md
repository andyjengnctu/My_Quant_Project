## 關鍵 shipped 模組索引

### Portfolio Core

- `core/portfolio_engine.py`只保留`run_portfolio_timeline()`日序 orchestration；benchmark cache、replay diagnostics、active-level rows與seed-ensemble aggregation分別由`portfolio_benchmark.py`、`portfolio_replay_support.py`、`portfolio_levels.py`、`portfolio_ensemble.py`持有canonical implementation。engine只以同function-object import保留歷史private helper相容名稱，不保存第二套實作。
- Entry path採三層責任：`portfolio_entry_plans.py`只建立reserved／cash-capped pre-market entry plan；`portfolio_entry_selection.py`是resource-aware policy thin router，Binary／Continuous共用搜尋在`portfolio_entry_selection_common.py`，Max-DL／feasible-ascent在`portfolio_entry_selection_max_dl.py`；`portfolio_entries.py`只保留reserved order fill、missed-buy記錄與extended-signal cleanup state transition。selection不得反向import`portfolio_entries.py`，所有實際成交仍由同一`execute_pre_market_entry_plan()`與exact-accounting執行。
- Portfolio Core split是infrastructure refactor，不改candidate validity、盤前reservation、fill、fee/tax、TP/SL、rotation、Round-Trip、resource-aware K/R0／stale-score semantics或Strategy Compare identity。Formal impact registry與coverage targets必須指向canonical split modules，compatibility façade coverage不得取代implementation coverage。

### 11B Strategy-aligned Daily Percentile Ranker

11B是獨立experiment profile `strategy_aligned_daily_percentile_mse`，不是新model architecture。它保留active 9A `inception_time_v1`的300×10輸入、RF229與原2-logit head，將`softmax(logits)[:, PASS]`視為0～1排序分數，對Selection內每個日期的`strategy_aligned_opportunity_r_v1` raw target percentile使用MSE。日期內採average rank，轉換為`(rank−1)/(n−1)`；同值共享平均rank，singleton固定0.5。不同日期互不共享位置、尺度或統計量，因此不建立跨年度normalization。

## Strategy Parameter Runtime Scientific Identity

Current strategy-parameter artifacts intentionally maintain two hashes. `compute_strategy_param_file_sha256()` is exact-byte integrity/provenance and may change when `created_at`, optimizer diagnostics, manifest/publication metadata, or formatting changes. `compute_strategy_param_scientific_sha256()` projects the artifact through `build_strategy_param_runtime_identity_payload()` and hashes only replay-affecting selector/ensemble policy, raw-universe contract, effective-date coverage and runtime parameter members. Strategy Compare replay metadata, Robustness benchmark/result identity and cross-run reuse must use the runtime-scientific hash; raw file/manifest hashes may be retained only as integrity/provenance or exact-byte legacy migration evidence. Re-publishing an unchanged runtime schedule must therefore remain REUSE/REPAIR-compatible, while any effective runtime parameter change must remain stale.

### MR-13P single-model conditional MFE-safety architecture

- `inception_time_conditional_mfe_safety_v1` 是 `inception_time_v1` 的研究型雙 head architecture identity：300×10 sequence encoder、InceptionTime backbone、global-average embedding與primary two-logit MFE head沿用既有結構；另新增一個 conditional-safety two-logit head。
- Primary head輸出 Pure-MFE rank score。Conditional head接收同一 shared latent 與 `stop-gradient(primary MFE softmax-pass probability)`；conditional loss不得回傳 primary-head weights，但兩個 head 的 loss 都可更新 shared encoder。這使 MFE 保持 primary axis，同時讓第二個 head學「在相同 MFE 水準下異常低 adverse」的 incremental safety signal。
- MR-13P training profile使用兩個同尺度 [0,1] same-date percentile targets與 full-list Delta-NDCG pairwise loss，固定等權平均，不設 scalar MFE/MAE fusion weight。Conditional target中的 future MFE/adverse只屬 supervision，不是 inference feature；checkpoint／Forward score分別保存 primary MFE 與 conditional-safety score，`model_score`仍只指 primary MFE。Forward Model Gate GO後，current PIT producer仍只建立一個shared-encoder checkpoint，並在同一fold score artifact同時保存`breakout_quality_score`／`primary_mfe_score`／`conditional_safety_score`；C64 runtime由同一artifact分欄消費Primary MFE與Conditional Safety，不建立第二模型或再次OLS residualize。

### Reverse-Conditional MFE A/B（MR-13Q / MR-13R）

- 共同supervision truth：每日`U=PctRank(Pure-MFE)`、`S=PctRank(-AdverseToMFEPeak)`，以同日含intercept OLS定義`J_raw=U-E(U|S)`，再以同日average-rank percentile形成final Conditional-MFE target。future truth只作label，不是inference feature。
- `MR-13Q / inception_time_v1`：Single-head；原InceptionTime shared representation直接輸出final Conditional-MFE two-logit head，模型與策略都只使用J score。
- `MR-13R / inception_time_safety_conditional_mfe_v1`：Duo-head research architecture。沿用相同300×10 InceptionTime backbone/global-average embedding，新增Raw Safety two-logit auxiliary head與Conditional-MFE two-logit final head。final head輸入為shared embedding拼接`stop-gradient(raw_safety_probability)`；final loss不能更新Safety classifier，但Safety/Conditional兩個loss都可更新shared encoder。
- Duo-head checkpoint與model spec必須固定兩head identity；canonical inference default/final output是Conditional-MFE，`raw_safety`只供model diagnostics，不直接參與strategy selector。MR-13Q/R的controlled comparison必須固定同一target、sample universe、Seed、pairwise reduction與strategy contract，避免把architecture差異與target/runtime差異混在一起。

- `core/training_policy.py`：Strategy Optimizer training policy 的 validation、derived snapshot、robustness seed resolver 與 runtime model-mode owner；`config/training_policy.py` 僅持有 declarative 使用者／專案設定。
- `core/selection_policy.py`：history-selection 策略參數 schema 與 default snapshot 的唯一 owner；避免 training policy 為 selection schema 依賴完整 breakout strategy module。

### Trading Canonical Provider Fetch Ownership（Round 6）

`services/trading/market_data_update.py` owns one process-local `services/downloader/finmind_shared_client.py::SharedFinMindRequestClient` across the execution-critical legacy producer and the V2 sidecar. The cache is request-identity scoped, never persisted as data truth, and may seed an exact-date request only from the raw rows of a semantically equivalent wider response of the same FinMind dataset. Large historical bulk chunks that have no downstream cross-consumer reuse are fetched uncached and filtered immediately, so request deduplication does not retain decades of full-market raw frames in RAM. `MarketDataBootstrapExecutor` asks the optional `will_issue_data_request()` capability before incrementing ledger HTTP attempts, so a cache hit remains one logical V2 request/commit but consumes zero provider data requests and zero local quota-attempt estimate.

Execution-critical Trading provider retries are explicit rather than hidden in either client. `services/downloader/finmind_http.py::request_finmind_data_with_retry` is the shared bounded-retry seam used by canonical PriceAdj bulk requests, per-ticker fallback and universe/market-date FinMind reads; it consumes the existing execution-policy retry budget/backoff, retries only provider-marked transient errors, and fails immediately on quota exhaustion or permanent errors. `FinMindHttpClient` and `SharedFinMindRequestClient` themselves remain one-call primitives, so Market Data V2 preflight/executor continue to own their independent retry/ledger semantics and provider-attempt accounting.

`TaiwanStockPriceAdj` remains FinMind-owned current-vintage adjusted-price truth. Round 6 must not replace the legacy full-history refresh with a recent append, because corporate-action revisions can change historical adjusted values. `services/downloader/trading_price_refresh.py` therefore chooses the lowest-provider-request exact strategy while preserving that full-history current-vintage semantic: when only a few local ticker CSVs are stale it retains per-ticker full-history fetch; when many are stale the bulk path is eligible only if every target ticker already has a readable legacy history baseline. The bulk path probes and fetches full-market `TaiwanStockPriceAdj` in config-driven six-month calendar ranges, proves every calendar-covered range contains all trading dates already published by `TaiwanStockTradingDate`, requires every cached/current actionable universe member to exist in the target-date PriceAdj payload, rejects any result that drops a date already present in any readable legacy CSV, and only then writes each per-ticker legacy CSV atomically. A missing, new or unreadable ticker history is never synthesized from an unproven bulk response: the canonical per-ticker producer requests FinMind `TaiwanStockPriceAdj` from the configured full-history start and validates that response before atomic publication. If a readable adjusted-price baseline exists, every baseline date must remain present; if no readable baseline exists, PriceAdj itself is the canonical current-vintage history and raw `TaiwanStockPrice` is deliberately not used as a full-history calendar oracle because the provider's raw and adjusted datasets can legitimately have historical date mismatches. Raw OHLC never becomes strategy price truth. Actionable universe members additionally require the confirmed target-date adjusted row, while required account holdings outside the actionable universe may legitimately remain on an older row during suspension. `services/downloader/universe.py` still uses exact-date `TaiwanStockPrice` only as independent current-universe traded-ticker evidence against exact-date PriceAdj before publishing a new universe cache, preventing a partial PriceAdj payload from silently shrinking the opportunity set. If any applicable completeness proof fails, the update is fail-closed and no partial CSV publication is allowed. No project-side adjusted-price calculation is introduced.

The same completeness contract continues through orchestration and lineage. `services/downloader/application.py` rechecks that every actionable universe CSV is current before returning `READY`; `services/trading/market_data_state.py` snapshot schema v2 persists `current_universe_tickers` plus `actionable_universe_exact_market_date_v1` and revalidates every member against the confirmed market date before publication. The aggregate dataset `MAX(Date)` remains part of content identity but can no longer mask a stale actionable member. Required holdings outside the actionable universe are still required to have a readable canonical CSV and may not contain future rows, but are not forced to fabricate a target-date row when trading is suspended. Because downstream Params/Scanner lineage binds the snapshot content hash, this per-member freshness proof is preserved by the existing content-bound lineage without creating another price source.

Trading physical dataset retention is intentionally broader than same-day new-buy eligibility. Because the canonical Trading Optimizer consumes the complete retained `data_dir`, every retained canonical CSV member must also stay on the same FinMind `TaiwanStockPriceAdj` current vintage: `services/downloader/application.py` derives retained updater membership from `core/trading_dataset_identity.py` and refreshes current universe + required holdings + retained CSV members together, while only `current_universe_tickers` receive the target-date/actionable freshness requirement. This keeps Optimizer/fingerprint membership current-vintage consistent without turning retained history into same-day eligibility. `services/scanner/scan_runner.py` therefore exposes an optional generic `ticker_membership` filter while preserving the existing default of scanning every discovered CSV for Research and other full-dataset callers. `services/trading/daily_workflow.py` is the Trading owner that passes the market-data snapshot `current_universe_tickers` into that filter; required holdings and historical tickers outside the current universe remain on disk for Optimizer, audit and position/exit management but are not scanned as new-buy candidates. Missing requested membership CSVs fail closed. Trading candidate snapshot schema v3 persists the exact sorted `scanned_tickers`, requires every candidate ticker to belong to that set, binds the market-data snapshot SHA in the currentness check, and rejects a candidate snapshot whenever the canonical current-universe membership changes even if the underlying dataset bytes and parameter artifact are otherwise unchanged. This separates historical retention, actionable membership and candidate lineage without deleting data or changing Research scanner semantics.

The default `PRICE_HISTORY_START_DATE=1994-10-01` aligns with FinMind's published `TaiwanStockPriceAdj` history boundary instead of spending provider requests on ranges where the dataset cannot contain rows. With six-month chunks, a new 2026-09-07 Trading day therefore requires 64 PriceAdj full-market range identities, 10 fewer than the former 1990-01-01 default, while preserving the same complete current-vintage history. The start boundary remains config-driven rather than validator-fixed. The completeness gates add one no-date `TaiwanStockTradingDate` request and one exact-date raw `TaiwanStockPrice` ticker-set evidence request during a fresh universe rebuild; the unchanged full V2 plan can reuse identical request identities through the shared process-local client where applicable. A missing/new/unreadable per-ticker baseline requires only its one PriceAdj full-history request; there is no second raw full-history date-evidence request. This is an operational request-geometry optimization only: the neutral registry fingerprint, full Trading V2 manifest identity and active rule-based Trading execution semantics must remain unchanged.

Round 6 closes the automatic execution-target gap with `services/trading/market_data_market_date_discovery.py`.  The state at `state/trading/market_data_v2/market_date_discovery_state.json` is operational-only and fingerprinted; it never enters Provider Snapshot, Research, registry, strategy, or parameter identity.  Scheduler wake-ups first resolve this local state.  Before the configured Price publication window (17:45), on weekends, or before `next_probe_at`, discovery is not due and costs zero provider calls.  A due discovery performs one `TaiwanStockPriceAdj` full-market current-range probe, retries a missing new date only with bounded 15/30/60-minute backoff, and otherwise advances to the next weekday.  If a new completed Trading day is observed, the same process-local `SharedFinMindRequestClient` is passed to `run_trading_market_data_update(..., sync_v2_archive=False)` so the execution-critical current-vintage CSV refresh and canonical Trading snapshot advance first while retaining the probe/cache.  Dataset V2 work then remains publication-driven through the canonical due planner rather than issuing a premature full 51-dataset sync.  Explicit `--target-date` bypasses market-date discovery for deterministic recovery/test runs.
